# authoring card — adopt

Purpose: On explicit Adopt invocation for `setup.unmanaged`, directly reverse-derive a brownfield repository's canonical devflow planning surface from maintained pre-devflow documentation, code, or both.

Failure scene: Adopt receives `setup.unmanaged`, mistakes material presence for completed evidence work, sends a documentation-only existing project to Product, asks for discoverable facts, or loops through Resume/Product instead of producing a proposal.

Observations: state kernel, route, current tracked-plus-untracked non-devflow material presence, bounded-refutation state, and binding approval.

Terminals: invalid state blocks; no maintained non-devflow project material routes to Product; managed state routes to Resume; an open Git operation asks the owner; a blocking or unavailable refutation stops before the binding question; refusal and interruption before approval write nothing; approved adoption reports and stops.

Evidence path: inventory every maintained source, reconcile claims, trace one evidence-grounded executable flow per code-backed capability candidate, cite the exact documentary basis for document-only candidates, derive Layer 0 and capability zones, and keep concise domain knowledge in the always-read capability document while placing document-abundance overflow in as many owner-adjacent K nodes as required. Before binding, one bounded clean-context semantic refutation records its scope, findings, and result in the proposal's Evidence verification section.

Human boundary: ask only irreducible decisions and contradictions, run the bounded refutation, then obtain one confirmation binding the complete proposed write set only when no blocking finding remains.

Commit boundary: under the one approval, commit complete Layer 0 and any idempotent follow-on record as `adopt — layer 0`, with product.md written last; then use that landed commit as Design head, write the capability documents followed by their K nodes, validate every capsule, and commit both as `adopt — capabilities`. Interruption remains unmanaged only while no current `.devflow` root or indexed path exists; current evidence returns recovery to canonical state. A post-product pre-commit diff is owner-directed Git recovery; after the first commit and before second-boundary writes Resume routes the managed missing baseline to Arch.

Consumers: the clean refuter receives the full draft, source dispositions, load-bearing current and proposed coordinates, the selected shared capability/capsule contract, and only the Surface and Required channel columns plus first proposal paragraph and ADR conditions from `<skill-root>/../arch/references/workflow.md`. Arch reads Layer 0 and capability zones; Direct reads product and architecture; Work and Resume read capability and knowledge documents.

Templates: templates/adoption-proposal.md, product.md, architecture.md, applicable design.md, code-style.md, glossary.md, capability-design.md, knowledge-node.md, and result.md.
