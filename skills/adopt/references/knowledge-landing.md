# Knowledge-landing execution contract

Consume only the current Decision's valid `marker.knowledge` entries. The collector calls the sibling `calculateState({ root })` API with the explicit supplied root; it accepts no CLI rendering, raw journal scan, or process-current-directory fallback. A route other than the exact valid `marker.knowledge-landing` route is not a landing invitation.

1. Open the exact `card-path@full-hash` source and record the supporting line range. Open only the marker's exact owner; never infer an owner or produce another marker.
2. Write a compact conclusion directly in that owner when it remains understandable there. Use a recursive K node only when the topic needs independent depth or reuse.
3. Put a root K node in the same-stem folder beside its owner and a child beside its parent. Scan the entire owner subtree before choosing an immutable `K-NNN` number; zero children is valid.
4. The final `Source basis` is a JSON array of exact `<card-path>@<full-hash>:<start>-<end>` strings. Do not write Parent, child index, manual index, residual, bundle, or batch metadata.
5. For multiple owners, choose only owners that can finish now. Delete only their byte-identical marker lines with their owner/K writes in one boundary commit, leaving every other marker intact. Re-run routing after the commit.

Marker-only deletion, a landing write without the matching deletion, an imprecise source range, a non-adopt writer, or a split commit is a failure.
