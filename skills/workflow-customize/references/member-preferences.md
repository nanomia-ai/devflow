# 팀원별 실행 방법 적용하기

개인 설정을 적용하는 소비 진입문과 작성하는 `workflow-customize`가 함께 쓰는 해석 기준이다.
적용·재개·실행 보고 규칙은 소비 실행에만 해당한다.

개인 선호는 반복 설명을 줄이되 다른 팀원도 같은 계약으로 이어갈 수 있게 해야 한다. 현재 조건에
맞는 방법은 현재 역할이 재량으로 고르는 방법보다 우선 적용하고, 현재 사용자의 명시 요청이 단순한
개인 선호를 바꾸면 그 요청을 따른다. 개인 설정은 프로젝트 정본·작업 계약이나 역할별 권한을 바꾸지
않는다. 파일 위치·상태·관리권·증거·정본 반영·종료는 기존 계약을 따르며, 명령이나 링크도 권한을
추가하지 않는다.

충돌하는 조항과 그에 의존하는 내용은 함께 제외하고 독립적으로 유효한 부분만 적용한다. 제외한 내용을
새 의도로 재해석하지 않는다. 빈 본문이나 무관한 조건은 기본 방법으로 진행한다. 읽기 실패·병합
충돌·해석 불가·내부 모순은 영향받는 부분을 적용하지 않고 이유를 알린다. 머리말 누락만으로 공유 작업을
손상으로 판단하거나 설정을 자동 수리하지 않는다. 실제 행동을 결정할 수 없을 때만 질문한다. 설정을
못 쓰는 것과 필수 계약·Git·관리권의 결함은 구별하며, 후자는 기존 중단·복구 규칙을 따른다.

개인 품질 문턱을 새 완료 기준으로 만들지 않는다. 추가 관찰에서 기존 검증 항목의 위반이 드러나면 그
항목의 증거로, 실제 계약·상위 판단 문제는 기존 인계로 다룬다. 선호 도구가 없다는 이유만으로 입증된
항목을 미입증으로 바꾸지 않되, 필수 관찰 수단이 없으면 `unproven`으로 남긴다.

새 진입·재개에서는 현재 설정을 읽고 같은 실행에서는 반복해서 읽지 않는다. 도중에 변경을 알게 되면
진행 중 행동을 안전하게 마친 경계에서 다시 판단한다. 실제 읽은 경로, 적용해 달라진 방법과 제외 이유를
기존 보고에 짧게 설명한다. 무설정 보고나 별도 설정 상태·로그는 만들지 않으며, 인계할 작업 사실과
증거는 기존 작업 문서에 남긴다.
