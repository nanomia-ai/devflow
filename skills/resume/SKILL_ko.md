# resume — 재개

목적: 새 세션이 다섯 가지 읽기로 상태를 복원하고 이어간다.

## 절차 — 이 순서 그대로

```
1. devflow/project/product.md 정체성 문단   ← 이 서비스가 무엇인지
2. devflow/tree/ 전체 목록                  ← 어디까지 왔는지 (.done. / .wip. / 대기)
3. 내 점유 카드가 있으면 통독               ← 진행 로그 포함. 어디서 멈췄는지
   (솔로 `.wip.` / 다중 `.wip-<내 id>.`. 다중: 남의 점유는 한 줄씩 목록만)
4. devflow/HANDOFF.md (다중: 내 방의 HANDOFF.md) ← 함정·배운 것·열린 결정
5. devflow/journal.md 전체 (있으면 — 정리 규율로 항상 짧다) ← 작업을 가로지르는 결정들
```

**HANDOFF는 신선도를 확인한 뒤에 믿는다.** 날짜를 최신 작업 커밋(`NN.N` 형식, wip 포함.
다중: 내 id 접두 커밋 또는 내 점유 카드 경로를 건드린 커밋)과 대조한다. 인계는 경계에서만 쓰이므로, 중간에 죽은 세션은 이전 경계의 파일을 남긴다 —
이미 밟은 다음 걸음을 지시하는 파일이다. HANDOFF 날짜 이후의 작업 커밋이 있으면 낡은
것으로 보고하고, 트리와 `.wip.` 카드가 결정한다. 날짜 헤더가 없어도 낡은 것으로 취급한다.
**HANDOFF와 트리가 충돌하면 트리가 이긴다.** 낡은 HANDOFF라도 '열린 결정'은 보고에 포함한다.

읽는 동안 규칙 정본의 **정합성 점검** 5항목을 함께 훑는다.
이상은 고치지 말고 아래 보고에 포함한다.

## 보고 후 승인

읽은 것을 **한 문단**으로 보고한다:

```
"<서비스>는 지금 <능력>까지 완료됐고, <작업>이 진행 중이었습니다.
진행 로그상 <마지막 지점>까지 됐고, 다음은 <한 걸음>입니다. 진행할까요?"
```

승인받으면 work로 이어간다. 승인 전에 코드를 고치지 않는다.

## 소화 — 다중 모드에서 남들의 작업 따라잡기

소화는 깨끗한 경계에서만 한다 — **내 점유 카드가 있으면 재개가 먼저다.** 소화는 그 카드가
닫힌 뒤, 또는 새 점유 직전에 한다.

```
1. 통합 브랜치를 당겨온다 (arch 설정)
2. 내 방 digest.md의 마커 이후 커밋 중 소화 대상을 고른다:
   작성자가 내가 아닌 것 전부 + 내가 작성했지만 메시지의 `<내 id> NN.N`이
   내 트리의 카드와 대응하지 않는 것 (= 내 세션 밖 작업)
3. 훑고, 공유 문서와 어긋나는 것은 발견→갱신 표로 착지시킨다.
   공유 문서를 고치게 되면 그것은 구속 결정이다 (규칙 정본 커밋 규율)
4. 잔량이 30건을 넘으면 커밋 단위로 걷지 않는다 — 경로·능력별 롤업(`git log --stat`)로
   한 번에 소화하거나 재기준선을 선언한다
5. 마커를 전진시키고 경계 정리 커밋에 동승시킨다
```

마커가 해석 불능이면(강제 push 등) 보고하고 사용자 확인으로 재정박한다 — 기본 후보는
내 마지막 커밋. 조용한 전량 재소화는 금지다. 마커 병합 충돌(내 두 머신)은 자손 해시를
남기고, 무관한 해시면 재정박 절차를 밟는다.

## 예외

- 내 점유가 없으면: 미점유 대기 카드 중 의존이 풀린 것을 제안한다.
  다중: 보고에 남의 점유 요약(누가 무엇을)을 한 줄 포함한다.
- HANDOFF가 없거나 비어 있으면: 정상이다. 트리만으로 재개한다.
- 트리 자체가 없으면: devflow 미적용 프로젝트다. product(신규) 또는 arch(기존 코드)를 안내한다.
