# 기획 증거 규율

이 동반 문서는 product·arch·adopt·split이 사실을 닫고 사용자 결정을 구속하기 전에 쓰는 공통 규율이다.

## 미지수 네 종류

| 미지수 | 답의 소유자 | 첫 행동 |
|---|---|---|
| 현재 저장소 사실 | 현재 code·config·manifest/lockfile·test·실행 결과 | 질문하지 않는다. 정확한 좌표나 유계 조회 한 번이면 직접 확인하고, 새 경로 추적·대조·반복은 격리 조사 기준을 적용한다 |
| 외부 계약 사실 | 고정 버전의 공식 문서·명세·소스·1차 API | 저장소에서 버전을 먼저 찾고 그 버전과 조회 시점을 고정한다. 최신 문서로 구버전을 증명하지 않는다 |
| 실행 사실 | 현재 환경에서 허용된 안전한 호출·렌더링·상태 전이 | 직접 실행하거나 기존 검증 창구로 관측한다. 쓰기·비용·권한이 필요하면 정확한 허가를 요청한다 |
| 소유자 결정 | 가치·우선순위·위험 감수·사용자 경험을 정하는 사용자 | 확인된 사실과 추천 이유를 붙여 질문하고 답 전에는 구속하지 않는다 |

## 차단 사실과 후속 사실

사실이 닫히지 않으면 현재 선택의 허용 여부나 완료 검증을 결정할 수 없을 때 `차단`이다.
차단 사실은 답·충돌·불가 중 하나가 나올 때까지 그 사실에 의존하는 다음 단계와 구속 결정을 멈춘다.
안전한 기본값으로 현재 결정을 구속할 수 있고 나중 결과가 최적화만 바꾸면 `후속`이다.
후속 사실은 현재 단계의 기존 거처에 상태와 바뀔 영향만 남기고 독립 작업을 계속한다.

## 출처 소유권

출처의 권위는 그 사실을 바꿀 수 있는 주체로 정한다. 그럴듯함이나 최신성만으로 권위를 정하지 않는다.

## 정지 조건

사실을 소유한 출처나 실행 결과가 답하면 `settled`다.
같은 권위의 출처가 양립하지 않으면 `conflicted`, 허용된 도구·권한으로 확인할 수 없으면 `unavailable`이다.
차단 사실이 `conflicted`·`unavailable`이면 충돌·부재와 그 때문에 구속할 수 없는 결정을 보고하고 멈춘다.

## 영속화

원시 조사 파일은 만들지 않는다. 결론·현재 결정에 미친 영향·정확한 출처만 기존 소유 문장에 남긴다.
product의 후속 사실은 `열린 질문`, arch는 안전한 기본값을 가진 `잠정값`과 `해소 카드`를 쓴다.
split은 목적지·완료 신호를 추측하게 만드는 미지수에 기존 `조사 카드`를 쓰고, adopt의 미래 결정은 소유 단계로 보낸다.
맞는 거처가 없으면 파일이나 카드를 만들지 않고 정확한 소유 단계를 보고한다.

## 격리 조사

코드 흐름·문서 구조·도메인 맥락 자체를 이해해야 다음 판단을 할 수 있으면 메인이 직접 읽는다.
정확한 경로·심볼·URL을 이미 알거나 출력 상한이 있는 조회 한 번이 새 출처를 따라가지 않고 답하면 메인이 직접 확인한다.
답만 필요하지만 새 경로·출처를 따라가거나 둘 이상을 대조하거나 같은 결정에 독립 사실 확인이 2개 이상이면, 플랫폼이 지원할 때 한 조사자에게 묶는다.
같은 탐색 범위는 현재 결정 하나에 필요하고 허용할 저장소 경로·외부 도메인·버전을 한 브리프에 열거할 수 있는 질문 집합이다.
질문별·출처별 조사자를 만들지 않는다. 원자료 이해와 답만 필요한지가 갈리면 메인이 소유한다.
조사자는 저장소와 외부 1차 출처를 읽고 검색만 하며 재위임·파일 쓰기·제품 코드·test·prototype 실행·결정을 하지 않는다.
반환은 `settled`·`conflicted`·`unavailable`, 질문별 결론, 정확한 내부 좌표 또는 외부 출처·버전·조회 시점, 적용 경계와 남은 충돌뿐이다.
탐색 transcript와 원시 출력은 반환하지 않는다. 메인은 구속 결정을 바꾸는 핵심 좌표만 확인하고 같은 범위를 전면 재탐색하지 않는다.
실행으로만 닫히는 사실은 메인이 허용된 안전 실행이나 기존 검증 창구로 관측한다.
prototype·코드 변경은 기존 조사 카드와 work로 보내고, 소유자 결정과 구속 결정은 조사자에게 맡기지 않는다.
격리 실행이 없으면 같은 범위를 메인이 직접 조사한다. 차단 사실의 반환 전에는 의존 결정을 구속하지 않는다.

## 실제 제시 선택지 기준

한 선택지가 뒤 질문의 필요·선택지·추천 기본값 중 하나를 바꾸면 두 질문은 의존한다.
의존 질문은 한 건을 먼저 닫고, 서로 바꾸지 않는 질문만 같은 묶음에 둔다.
사용자의 자유 입력 뒤에는 실제 답으로 남은 의존과 추천 기본값을 다시 계산한다.

## 구속 전 재검토

현재 결정 묶음을 구속하기 직전에 다음 네 조건을 모두 만족하는 실질 후보가 있을 때만 하나를 비교한다.

1. 현재 증거 또는 이미 허용된 조사 발동의 증거로 설명할 수 있다.
2. 사용자 결과·제품 경계·되돌리기 비용·검증 가능성 중 하나를 실질적으로 바꾼다.
3. 이름이나 표현만 다른 안이 아니라 다른 trade-off가 있다.
4. 현재 단계의 소유권 안에서 비교할 수 있다.

후보가 없으면 출력·질문·조사·기록을 만들지 않는다. 후보가 여럿이면 성공 판정과 사용자 우선순위가 하나를 가를 때만 하나를 제안한다.
가르지 못하면 현재 안을 유지한다. 사용자가 재선택한 묶음에는 구속 전 재검토를 다시 적용하지 않는다.

| 소비자 | 사실 확인 지점 | 구속 전 재검토 지점 | 넘지 않는 경계 |
|---|---|---|---|
| product | 현재 질문 프런티어를 사용자에게 묻기 전 | 답 반영 뒤 다음 프런티어 생성 또는 최종 확인 전 | stack·DB를 선택하지 않는다 |
| arch | 후보를 사용자에게 올리기 전 | 후보 생존 사실 확인 뒤 되돌리기 어려운 선택을 구속하기 전 | product의 문제·능력·경계·성공 판정을 바꾸지 않는다 |
| adopt | 현재 구현·고정 버전 외부 계약을 preview하기 전 | 관찰·해석·미래 결정을 나눈 뒤 확인 전 | 대표 흐름의 구조 이해를 위임하거나 현재 사실을 미래 의도로 승격하지 않는다 |
| split | 유지보수 등급의 출처를 읽을 때 | 카드 네 필드가 처음 유일해진 뒤 카드 착지 전 | Layer 0 변화는 비교하지 않고 2a로 환류한다 |
