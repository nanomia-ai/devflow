# Output schema guide

Use the registered templates exactly.

- `proposal.md` is a report surface only. It holds unresolved choices and approval review; it is never written as current Layer 0.
- `architecture.md` owns the current technical decisions, grounds, discarded alternatives, Provisional values, risks, exclusions, verified channel record, integration branch, and merge mode.
- `code-style.md` is one page of priorities, project-specific derived choices, trust posture/boundaries, and non-goals. It states what the project values, not implementation procedure.
- `adr.md` is created only for a decision meeting all three ADR conditions.
- `capability-design.md` has the exact five-line header, fixed design headings, one verified-zone boundary, and an initially empty verified scaffold. Existing valid verified bytes are preserved.
- `knowledge-node.md` is free-body recursive K with no footer or one exact, nonempty, strongly validated final Source basis. Physical same-stem folders encode recursion; the document has no parent or index field.

Every placeholder is supplied from the current Decision's declared artifacts and the domain work it authorizes. Never use the migration atom ledger as content.
