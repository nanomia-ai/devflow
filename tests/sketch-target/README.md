# Sketch target preflight

This experiment attacks the Phase 7 claim that one small Sketch contract can preserve either a
project idea or a change-blocking question without becoming a research archive or a Work artifact.
Every behavior observation uses a fresh Codex Sol High session in YOLO mode with only the
project-local Sketch target installed.

Observe separately:

- whether a durable Sketch is created only when the question must survive the turn;
- project versus change scope and the chosen destination owner;
- brief, current state, optional finding, and index ownership;
- recovery from current files without transcript reconstruction;
- whether the conclusion handed off is narrower than the exploration; and
- delivery evidence versus fresh-session behavior.

## Result

Verdict: **proven on this host for project creation, transcript-free project recovery, and
change-decision recovery.**

Package evidence (Core `1.0.3`, package `0.3.0`):

- two consecutive builds produced tree
  `de4c5df0ab10319394716b206acd0ec919b1358544e1d8223b8403b8e55d130b`;
- `skill-rails check` reported `artifactIntact: true` and `sourceCurrent: true`.

### A — uncertain project idea

One fresh Codex Sol High session read the fixture entry, Sketch target, project gate, shared
project-knowledge contract, and Git state. With no prior `.devflow/`, it created exactly one index,
one project-scope brief, and one current state. It created no finding child, Product, Architecture,
Work artifact, or implementation.

The brief separated the governing automated-check versus manual-inbox question, established facts,
non-scope, and a behavioral decision condition. State kept one Product-destined unresolved finding
and one bounded comparison whose signal was substantive runbook correction rather than clicks or
stated preference. The index exposed only bounded recovery globs and foundation readiness, not the
active artifact ID or its evidence.

### B — transcript-free project recovery

A different fresh session began from the committed index, brief, and state plus the new cohort
evidence. It found the active Sketch through the index/state route, opened its sibling brief, and
updated those two current files without creating another artifact or reconstructing a transcript.

The result distinguished observed Git/cohort facts from its bounded interpretation, excluded the
wiki-only teams from the conclusion, cleared `unresolved_findings`, and routed one Product landing:
the first release may promise repository-native freshness checks in the existing pull-request path.
It did not publish Product or delete the Sketch before absorption.

### C — interrupted change decision

One fresh session read the ready foundation, the pre-existing change brief and state, the consumer
evidence in the prompt, target references, and Git. It replaced the brief's unknown with the current
consumer evidence and conclusion, then published `next_route: direct` with an empty unresolved
list. The conclusion excludes storage-local identifiers from backup export and adds no project
canon because Architecture already owns identifier locality.

No Work contract, finding child, code, project-canon edit, or early Sketch deletion appeared. The
project and change cases used the same brief/state shape without Work's acceptance, write boundary,
base revision, verification, or implementation custody. For these cases, an independent Sketch is
simpler than treating exploration as a Work subtype while preserving the user-requested exploration
entry.

## Reopen boundaries

- A concise artifact is not successful unless a later session can recover one next action from it.
- A polished research narrative is a failure if it does not change Product or Direct's decision.
- No research method, transcript store, Work subtype, renderer, or state schema is implied by these
  cases.
- Actual Product/Direct absorption and final Sketch deletion, optional independently selected
  findings, external research, team handoff, cross-host repetition, and an ephemeral same-turn
  Sketch outcome remain unproven.
