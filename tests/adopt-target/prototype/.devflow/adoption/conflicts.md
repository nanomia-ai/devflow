# Referenced-category deletion

The maintained operations guide says deleting a category retains its expenses as `Uncategorized`.
The store returns `false` instead, and the executable test requires that rejection. Both concern the
same referenced-category action; renaming and unreferenced deletion do not resolve the conflict.

If prose wins, Product/Category meaning and implementation must change. If executable behavior wins,
the Categories canon and old guide must say deletion is rejected while references exist. Source
authority alone cannot choose the user-visible promise. The required decision route is `user`; the
conflict closes when the owner chooses one rule and the chosen rule is self-contained in Categories.
