# Verify: 실행 결과로만 판정하기

## 시작

먼저 `../principles/SKILL.md`, `pilot/brief.md`, `pilot/plan.md`, `pilot/progress.md`를 읽는다.
이 스킬의 질문은 "성공 기준을 실제로 확인했는가, 아니면 무엇이 아직 확인되지 않았는가?"이다.

가능하면 구현 세션과 다른 새 AI 세션에서 수행한다. 구현 설명이 아니라 문서와 대상 프로젝트의
현재 바이트, 그리고 직접 실행한 결과를 근거로 삼는다.

## 할 일

1. 완료 기록이 있는 카드 하나를 고르고, 그 카드의 완료 기준과 `brief.md`의 관련 성공 기준을
   각각 독립적인 실행 또는 관찰 단계로 바꾼다.
2. 카드가 약속한 검증뿐 아니라, 성공 기준에 직접 필요한 기존 행동 보존도 확인한다.
3. 각 기준을 직접 실행하고 증거를 적는다. 실행하지 못했으면 그 이유를 적고 `unproven`으로 둔다.
4. 결과를 다음 셋 중 하나로 판정한다.
   - **pass**: 모든 성공 기준과 필요한 기존 행동을 직접 확인했다.
   - **fail**: 하나 이상의 성공 기준이 재현 가능하게 실패했다.
   - **unproven**: 필요한 실행을 하지 못했거나 결과가 충분히 관찰되지 않았다.
5. `pilot/verification.md`에 카드별 결과를 추가한 뒤 사용자에게 결과를 보고한다. fail이면 실패
   장면을 보이되, 이 스킬이 코드를 직접 고치지는 않는다.

## `pilot/verification.md`에 남길 항목

- 검사한 카드 식별자, 해당 성공 기준, 각각의 실행 단계
- 관찰한 결과와 근거
- 기존 행동 보존 검사 결과
- 최종 판정: `pass`, `fail`, 또는 `unproven`
- fail 또는 unproven의 정확한 이유와 다음 행동 제안

## 끝낼 때

테스트가 몇 개 통과했는지로 성공을 대신하지 않는다. 성공 기준 하나라도 실행하지 못했다면
`pass`라고 쓰지 않는다. 이 스킬은 수리하지 않으며, fail의 수리는 새 작업으로 Direct에서 다시
계획하고 사용자 승인 뒤 수행한다.
