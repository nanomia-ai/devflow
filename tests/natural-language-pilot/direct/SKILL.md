# Direct: 한 번에 할 작업 정하기

## 시작

먼저 `../principles/SKILL.md`와 대상 프로젝트의 `pilot/brief.md`를 읽는다. 이 스킬의 질문은
"승인된 성공 기준을 가장 작은 안전한 변경으로 만족하려면 지금 무엇을 해야 하는가?"이다.

`pilot/brief.md`가 없거나 승인 여부가 불분명하면 작업 계획을 만들지 말고 Product로 돌아가야
한다고 보고한다.

## 읽을 것

- `pilot/brief.md`
- 성공 기준과 직접 연결된 코드, 테스트, 실행 방법
- 해당 부분의 기존 동작을 보이는 최소 파일

## 할 일

1. 성공 기준 하나하나를 코드 또는 테스트의 구체적인 위치와 연결한다.
2. 요청을 한 번의 구현 작업으로 끝낼 수 있는지 판단한다. 둘 또는 세 카드가 더 자연스럽다면
   카드마다 앞서 완료되어야 하는 카드를 적는다. 세 장을 넘기거나 의존 관계가 순환하면 이 파일럿의
   범위를 넘은 것이므로 사용자에게 범위를 나눌 방법을 제안한다.
3. 작업 카드 초안을 만든다. 구현 방법은 충분히 구체적으로 쓰되, 아직 읽지 않은 코드에 대한
   추정을 사실처럼 쓰지 않는다.
4. 사용자에게 변경 경로, 제외 범위, 검증 방법을 보여 승인받는다.
5. 승인된 뒤에만 `pilot/plan.md`를 만든다. Product가 새 brief를 승인했다면, 이전 plan을 계속
   쓰지 않고 새 brief에 맞춰 계획을 갱신한 뒤 다시 승인받는다.

## `pilot/plan.md`에 남길 항목

- 이 계획이 만족할 `brief.md`의 성공 기준
- 카드 1~3장. 각 카드는 식별자(T1처럼), 목적, 바꿀 파일 또는 코드 영역과 이유, 의존 카드,
  완료 기준, 하지 않을 변경을 가진다
- 새 계획이면 이전 계획에서 대체한 카드와 이유. 새 카드는 이전 카드 식별자를 다시 쓰지 않는다
- 카드별 검증 방법과 기대 결과
- 계획 승인 사실
- 다음 단계: `work`가 의존 카드의 현재 `pass` 검증 결과가 있는 카드 하나와 필요한 소스만 읽어 구현한다

## 끝낼 때

이 스킬은 코드를 고치지 않는다. 검증 방법을 실행할 수 없거나, 카드가 제품 정의보다 넓어졌다면
작업을 승인받지 말고 Product로 돌아가 범위를 다시 정한다.
