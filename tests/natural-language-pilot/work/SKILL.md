# Work: 승인된 한 작업 구현하기

## 시작

먼저 `../principles/SKILL.md`, `pilot/brief.md`, `pilot/plan.md`, 그리고 있으면 `pilot/progress.md`를 읽는다. 이 스킬의 질문은
"승인된 카드만 구현하고, 무엇을 실제로 했는지 다음 AI가 재현할 수 있게 남길 수 있는가?"이다.

작업 계획이 없거나 승인 사실이 없으면 코드를 바꾸지 않는다. 의존 카드의 현재 `pass` 검증 결과가
없는 카드를 고르거나, 카드가 현재 코드와 명백히 맞지 않으면 조용히 재계획하지 말고 차이를 보고하고
Direct로 돌려보낸다.

## 할 일

1. 계획에서 실행할 카드 하나를 고른다. 이전 카드의 현재 `pass` 검증 결과와 현재 카드의 범위가 맞는지 먼저 확인한다.
2. 카드가 지정한 파일과 그 직접 의존 파일을 읽어 현재 동작을 확인한다.
3. 카드 범위 안에서 가장 작은 변경을 구현한다.
4. 카드가 정한 검증을 실행한다. 실패하면 실패 장면과 현재 가설을 기록한다. 실패를 숨기기 위해
   범위를 넓히거나 테스트를 약하게 만들지 않는다.
5. 구현을 끝냈다고 생각해도 성공을 선언하지 않는다. 실행 사실과 남은 한계를 `pilot/progress.md`에
   남기고 Verify로 인계한다.

## `pilot/progress.md`에 남길 항목

- 카드 식별자와 시작·완료 또는 막힌 결과
- 실제로 바꾼 파일과 변경 이유
- 카드의 각 항목에 대해 한 일
- 실행한 명령 또는 수동 단계와 그 결과
- 실패한 실행이 있다면 재현 방법과 현재 상태
- 구현자가 확인하지 못한 미검증 항목
- 다음 단계: 완료된 카드라면 `verify`가 이 문서와 카드의 성공 기준을 독립적으로 검사한다.
  막혔다면 Resume이 사람에게 필요한 판단을 보고한다

## 끝낼 때

이 스킬은 검증 결과를 판정하지 않고, 요청 밖의 리팩터링을 추가하지 않는다. 변경이 카드의
완료 기준을 만족하지 못하면 진행 기록에 막힘을 남기고 사용자 또는 Direct의 다음 판단을 기다린다.
