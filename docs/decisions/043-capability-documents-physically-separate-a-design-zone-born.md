# DD-43 · 능력 문서는 Layer 0에서 태어나는 설계 구역과 폐쇄에서 갱신되는 검증 구역을 물리적으로 나누며 항상 켠다

- 상태: 유효 · 일부 정정 → DD-76 (v0.18.1), DD-91 (v0.19.0), DD-92 (v0.20.0), DD-97 (v0.21.0)
- 주제: 지식층과 능력 문서
- 도입: v0.11.0

소유자 의도는 새 MVP·브라운필드·중기 합류 모두 첫 카드 전부터 도메인 경계와 개념을 얻고, 카드 배선 없이 번호로 도달하는 것이다. 설계 구역은 arch(브라운필드는 adopt), 검증 구역은 verify가 고정 `## Verified state` 경계의 서로 다른 byte 범위를 전면 교체한다. 이는 v0.10.0의 한 작성자 근거를 뒤집지 않고 분해한다: 두 작성 시점은 직렬이고, 공유 byte가 없으며, 설계는 `Design head`, 검증은 `Scope head`·`Covered cards`로 서로 다른 신뢰를 밝힌다. 단일 기계 블록은 두 소유자의 byte를 다시 겹치게 하므로 설계 메타데이터 2필드는 경계 앞, 검증 메타데이터 5필드는 경계 뒤에 둔다. 스위치를 없앤 근거는 채택안이 1,100~1,700줄 중계노트형 제2 인계층이 아니라 능력당 약 185줄·연대기 금지·카드당 O(1) 읽기라는 점, 그리고 소형 프로젝트도 6절짜리 설계 구역으로 같은 생애를 얻는다는 점이다. 설계 신선도 입력은 실제 원천인 product.md·arch.md·glossary.md만 쓴다. code-style.md·design.md를 넣으면 해당 구역을 바꿀 실패 경로 없이 전 능력을 가설로 만드는 과잉 하네스다. 정확한 v0.10 선행 형식은 손상 초기화와 분리해 설계만 현재 Layer 0에서 재도출하고 검증 본문과 호환 메타데이터를 기계 이관하되, 소비 경로를 입력으로 삼지 않았던 옛 `Scope head`는 승계하지 않아 다음 능력 폐쇄 전까지 검증 진술을 가설로 둔다
