# DD-83 · 정본이 이미 고정한 전이의 완전 상태와 디스크의 차이를 한 읽기 전용 계산이 진입과 각 승객의 커밋 직전에 보인다

- 상태: 유효
- 주제: 정체성 · 배포 · 플랫폼
- 도입: v0.19.0
- 날짜: 2026-08-22
- 날짜 근거: git 추정 (CHANGELOG에 해당 버전 없음)

관측된 문제: 첫 실사용의 81 커밋을 대조했더니 **자기 산출물과 자기 커밋을 가진 의무는 한 번도
안 빠졌고**(카드 상태 rename · task 커밋 · `verify.md` · 진행 로그 · 커밋 메시지 형식),
**남의 커밋에 얹혀 가는 의무만 마모됐다**(다이제스트 marker 전진 · HANDOFF 갱신 · 최종 카드의
`carry:` · arch 채널 확인). 정본은 HANDOFF를 스스로 *"it only rides here"* 라고 승객으로
배선한다. 무효인 전제는 「AI가 규칙을 따른다」가 아니라 **「명확하게 쓰면 실행된다」**였다 —
같은 기록에서 세션들은 자기에게 불리한 규칙 넷을 정확히 지켰다.

원하는 동작: 의무마다 규칙이나 커밋을 늘리지 않는다. 정본이 이미 열거한 전이의 완전 상태와
현재 디스크 상태의 차이를 도구가 보여 주고, 모델이 그 사실을 보고 의미를 판단해 행동한다.

선택한 경계: 하나의 계산
`정본이 이미 고정한 전이의 완전 상태 − 현재 디스크 상태 = missing` 을 세션 진입과 각 승객을
실을 커밋 직전에 쓴다. 진입에서 부르면 **이미 빠진 것을 발견**한다. 최종 작업 커밋 직전에는
현재 점유의 `carry=absent|present`를, 경계 정리 커밋 직전에는 `missing=[carry|handoff]`를 보고
**각 탈것이 떠나기 전에 막는다.** 기존 출력 종류에 사실 필드를 붙인다(`finish-boundary missing=[…]` ·
`claim.mine carry=absent|present` · `layer.children-done carry=N`). 새 출력 종류는 디스크에
별도 대상이 있는 `ready.digest-behind` 하나만 허용한다. **도구는 rename·기록·stage·commit을
실행하지 않는다** — DD-80 ④의 읽기 전용·무상태가 그대로다. 기록은 새 필드를 복사하지 않고
기존 사실에서 투영한다: `report: origin=…` 은 카드 생성 커밋과 그 커밋에서 삭제된 요청·층
열기 표식에서 계산하고, 원래 입력이 없으면 `none`, 얕은 이력이나 다중 매칭이면 이유와 함께
`unknown` 이다. 카드에 새 `Origin:` 의무는 만들지 않는다.

필요한 이유: 관측된 실패는 전부 **감지 자체가 0**이었던 장면이다. 감지가 0인 곳에 쓰기 권한을
늘리면 해결되는 것은 없고 권한·입력·호출 의무만 새로 생긴다. 같은 계산을 진입과 각 실제 커밋
경계에 쓰면 복구와 예방이 한 정의를 공유하고, 승객을 실을 커밋이 떠난 뒤에 검사하는 한 커밋
늦은 경로도 남지 않는다.

기각한 대안: **별도 boundary writer**(도구가 rename·기록·commit을 실행) — 통합 merge/rebase를
품지 못하고, 새 권한·입력·호출 의무를 만들며, 지금 증거로는 추가 값이 없다. 사용자 선택이
아니라 증거상 열등한 안이다. **다시 여는 조건**은 실사용에서 「도구가 누락을 정확히 잡았는데
같은 세션이 경계를 닫지 못했다」가 실제로 나오는 것이다. **상태 조회의 쓰기 겸용** — 읽기
전용이 이 도구의 정체성이므로 한 부름 안에서 겸하면 그 정체성이 사라진다. **의무마다 새 국소
규칙** — 마모의 원인이 규칙 부족이 아니라 관측 부재라는 위 진단을 정면으로 부정한다.
**카드 `Origin:` 필드** — planning commit 성공과 무관한 새 승객을 하나 더 만든다.

영향 좌표: `skills/principles/scripts/project-state.mjs`, `scripts/project-state.test.js`,
경계 사실을 읽는 `skills/{work,split,verify,resume}/SKILL{,_ko}.md`.
재검토 조건: 위의 writer 재개 조건이 실사용에서 관측될 때. 또는 `missing` 이 실제로는 안 빠진
것을 빠졌다고 불러 세션이 헛일을 하는 장면이 나올 때.
