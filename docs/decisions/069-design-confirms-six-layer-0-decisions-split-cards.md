# DD-69 · design은 여섯 Layer 0 결정을 확정하고 구축은 split 카드가 소유하며 결과 사실만 design.md로 환류한다

- 상태: 유효 · 일부 정정 → DD-99 (v0.22.0)
- 주제: 작업 트리와 카드
- 도입: v0.15.2
- 최종 검토: 2026-09-11

종전 design은 트리보다 먼저 도는 선택 단계이면서 토큰 파일과 `/preview`를 본체·완료 신호로 요구했다. 빈 저장소에는 실행할 앱도 코드 산출물을 소유할 카드도 없어, 문서는 기획하고 실물은 만든다는 두 해석이 한 스킬 안에서 갈렸다. design의 산출은 접근 방식·디자인 원천·토큰 전략·컴포넌트 전략·분해 축·검토 표면이라는 여섯 Layer 0 결정과 구축 범위를 담은 design.md 하나다. 여섯 필드는 파일 부재와 무관하게 Layer 0이며 `안 함`·`없음`과 이유도 값이다. 사용자가 문서를 확인하면 기존 `design — design.md` Layer 0 커밋으로 끝나고, 토큰·테마·컴포넌트·프리뷰 구축은 split 카드와 그 실행 제안이 소유한다.

트리 뒤 최초 진입과 방향 변경은 DD-50의 기록-먼저 길 하나를 쓴다. split이 원 요청을 `유지보수 라우팅 대기`에 먼저 착지하고 2a로 design에 보낸다. design 커밋까지 그 줄을 보존했다가 split이 같은 출처에서 카드와 실행 제안을 계획할 때 소비한다. 기존 카드는 상위 문서 변경 계약대로 함께 참이면 유지하고 아니면 `.stale.`·재분할한다. 새 상태·새 커밋 종류·진행 원장은 만들지 않는다.

구축이 예정 경로·이름·명령을 확정한 사실은 발견→갱신 표가 design.md의 정확한 한 줄을 교체한다. 여섯 결정의 방향이 바뀌면 같은 기록-먼저 길로 design 확인을 다시 받는다. DR-12는 표 일원화가 실패한 이유로 “표에 착지 칸이 없는 틀린 쪽이 존재한다 (design.md · 이미 있는 code-style 줄 · 실행은 되지만 틀린 완료 신호)”를 기록했다. 이 결정은 위반 때의 기존 문서 계층 절차를 없애지 않고 design.md에 없던 착지 칸 하나만 더하므로 그 기각안을 재제안하지 않는다. DD-43의 신선도 입력에도 design.md를 더하지 않는다.
