# DD-25 · 준비된 카드의 정의·카드별 실행 제안 승인·재개 라우팅은 디스크 상태로 판정한다

- 상태: 유효 · 일부 정정 → DD-80 (v0.18.7), DD-92 (v0.20.0)
- 주제: 작업 트리와 카드
- 도입: v0.9.21
- 최종 수정: 2026-08-30

두 독립 문자 실행에서 세션 경계의 결정적 막힘이 교차 확인됐다: 완료된 `의존`을 가진 카드가 "의존 없음" 문구 때문에 영원히 점유 불가, 도입 뒤 split 전에 세션이 끝나면 adopt↔resume 순환, resume이 split·verify 경계에서도 work만 호출, 일반 실행 제안 승인은 디스크에 흔적이 없어 다음 세션이 승인 전후를 구분 불가. 준비됨은 `의존`이 `없음`이거나 쉼표로 나뉜 번호마다 정확히 하나의 `.done.` 카드가 있다는 뜻이다. 새 카드의 `의존` 형식은 하나로 고정한다. `승인`·`검토` 중 하나라도 없는 카드만 구형으로 판정하고 선두 번호를 기계적으로 읽어 다음 계획 때 정규화하며, 해석 불가능한 항목은 사용자가 정한다. 작업 카드 판정은 `state-predicates`, revision·사건 판정은 `verification-predicates`가 각각 한 번만 소유한다. 전자는 split·work·verify·resume, 후자는 verify·resume의 Claude·Codex 입력에만 들어간다. 승인·병렬 묶음·검토 정책은 각 카드 필드에 두고 계획 커밋으로 착지시키며, 배정은 점유 접미사만 맡는다. 승인은 authority에 같은 경로가 있고 index·working tree가 솔로 HEAD 또는 fetch한 다중 통합 브랜치와 Git 정규화 비교에서 모두 같을 때만 유효하다. 범위 밖 선행 작업은 새 카드·원 카드의 `의존`·승인·원 카드 해제를 계획 커밋 하나로 바꾼다. resume 상태표는 부분 트리·은퇴 능력·막힌 의존·완료 제품까지 판정한다. 카드 2개 분할을 금지하던 산술 충돌도 제거했다
