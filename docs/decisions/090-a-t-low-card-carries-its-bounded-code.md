# DD-90 · T-하 카드는 유계한 코드 근거와 필수 제약을 나르고, 작업 전용 완료 신호는 이름 댄 fixture를 소유한다

관측된 문제: 낮은 등급의 백업·내보내기 카드가 work가 자동으로 읽는 상위 문서만으로 승인될 수
있었다. 다음 실행자는 확정된 저장소나 envelope 소비자 경로도, 내보내기 전에 현재 상태를
소비해야 한다는 문장도 받지 못하므로 그럴듯한 낡은 snapshot을 상대로 구현하고도 카드를 문자
그대로 충족할 수 있었다. 또 완료 신호가 작업 전용 fixture를 이름 대면서 어느 목적지도 그
fixture를 소유하지 않는 책임 공백이 있었다. 명령은 미선언 산출물을 만들거나 의존한 채 통과하고,
다음 작업자는 약속한 결과를 바꿨다는 표지 없이 범위 밖 파일로 지울 수 있었다.

선택한 경계: 확정된 제공자나 현재 소비자를 쓰는 T-하 작업은 그 계약을 드러내는 최소한의
유계한 구체 경로만 `읽을 것`에 적고, 필수 순서·데이터 흐름 제약은 목적지나 금지가 나른다.
실제 그린필드나 독립 작업은 명시적인 해당 없음 형식 하나를 쓴다. 모든 완료 신호는 기대 관측과
그 관측이 무엇을 증명하는지 말한다. 작업 전용 테스트·fixture 경로를 이름 대면 목적지가 그
정확한 경로를 산출물로 선언한다. 그런 경로가 없는 넓은 suite 명령은 경로 선언에서만 면제되고
증명 진술에서는 면제되지 않는다. work는 점유·재개 전에 계약을 검사하고 부실한 카드를 기존
수리 경로로 split에 돌려보낸다.

필요한 이유: 자동 기준선 문서는 도메인을 설명하지만 기계적 실행자가 소비해야 할 현재 코드
edge를 식별하지 않는다. 명령은 카드가 이름 댄 assertion만 증명하며, 작업 전용 fixture가 명령
안에만 있으면 내구 소유자가 없다. 이는 실행 경계이지 구현 지시가 아니다. 복합 카드 하나는
여전히 여러 능력에 영향을 줄 수 있고, 경로는 전수가 아니라 유계로 남으며, 지식 승격은 카드
번호가 아니라 의미 소유자에게 계속 착지한다.

기각한 대안: 가능한 코드 경로 전부 — 무유계이고 카드를 코드 지도로 만든다. 능력마다 카드 하나
— 복합 카드 유연성을 회귀시킨다. 제공자 진실을 카드에 복사 — 정본 소유자를 중복한다. 자동
읽기를 T-하 근거로 인정 — 관측된 소비자 edge 누락을 재현한다. 넓은 suite의 테스트 전부 선언
— 책임은 늘지 않고 잡음만 는다. 구현 방법 처방 — 카드 하네스 경계와 충돌한다.

DD-44 정정 근거(v0.23.20에서 누락 기록 복구): cold Direct가 자동 Layer 0·현재 능력 경로를
`읽을 것`에 복제하면서 구체 provider/consumer code/test 경로를 빠뜨리자 Work가 구현 전에
`missing-bounded-basis`로 멈췄다. 이는 DD-90이 이미 기각한 “자동 읽기를 T-하 근거로 인정”
장면이다. DD-44의 번호 규칙 소유권은 유지하고, v0.10 카드의 중복 기준선 경로를 조용히 넘긴다는
절만 정정한다. 현재 좌표는 Direct의 `spec.mjs`·`body.md`·`authoring-card.md`, Principles의
`references/knowledge/inputs-and-entry.md`, Work의 `body.md`와 기존 basis collector, 매트릭스 §3.23과
두 표적 test다.

영향 좌표: `skills/split/SKILL{,_ko}.md`의 작업 카드 작성·수리,
`skills/work/SKILL{,_ko}.md`의 점유·재개·위임 사전 점검, A17 매트릭스 칸, 저장소 invariant
fixture. DD-24·DD-25·DD-50·DD-55·DD-69는 그대로 유효하다.
재검토 조건: 유계 경로가 구현 처방 없이 소비 계약을 식별할 수 없음이 실측되거나, 작업 전용
fixture가 완료 계약 중복 없이 다른 내구 소유자를 얻을 때.
