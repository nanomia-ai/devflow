# DD-50 · 변경 요청은 즉시 기록하고 나중에 계획한다. 완료 신호는 그 능력으로 좁힌다

- 상태: 유효
- 주제: 작업 트리와 카드
- 도입: v0.12.0
- 결정일: 2026-08-13
- 최종 수정: 2026-08-13

진행 중인 작업을 어떻게 할 것인가라는 한 문제의 두 반쪽이다. 유지보수 행을 점유 아래에 두면 점유가 여러 단위에 흔해진 뒤 요청이 아예 기록되지 않고, 라우팅 전체를 위에 두면 지나가는 말 한마디가 카드를 중단시킨다. 행을 쪼개면 둘 다 닫힌다 — 기록은 점유보다 위, 계획은 아래. 나머지 반쪽은 빌드다. 능력 전환에는 절차가 필요 없어야 했지만, 한 단위의 반쯤 짠 코드가 다음 단위의 완료 신호를 실패시키고 실패 사다리가 멀쩡한 카드를 결함으로 취급해 3회 만에 사람을 부른다. 장치 둘이 닫는다: 전환이 이미 바꾼 것을 체크포인트하고, split이 신호를 그 능력이 소유한 경로로 좁힌다. 두 번째가 한 작업 트리의 터미널 둘을 견딜 수 있게 만드는 것인데 기획은 그것을 권고로 남겨 두었다
