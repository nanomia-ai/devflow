# DD-114 · 라운드 기록 계층을 제거하고, 그것이 담던 것을 세션이 실제로 읽는 소유자에게 옮긴다

- 상태: 유효
- 주제: 정체성 · 배포 · 플랫폼
- 도입: v0.26.0
- 최종 검토: 2026-09-11

관측된 문제: `docs/rounds/` 는 **76 파일 1,970 KB** 였다. 정본 문서가 이름 부르는 것은
**5편**이고, CHANGELOG 와 라운드 상호 인용까지 포함해 **어디에서도 한 번도 불리지 않는 것이 39편
868 KB(44%)** 였다. 이 계층의 진짜 비용은 크기가 아니라 그 안에 좌초한 것이다:
`v0.13.0/plan_ko.md` §2 「소유자가 원하는 것 — 모든 판단의 근거」와 §3 「소유자와 일하는 법 — 실패로
배운 계약」은 각각 *"이 절을 모르면 판단을 못 한다"*, *"이걸 어기면 작업이 반려되거나 무한 루프에
빠진다"* 로 시작하는데 **둘 다 여는 배선 행이 없었다.** `v0.12.0/handoff_ko.md` §2(실패의 역사)와
§10(잃으면 안 되는 것)도 같다. 소유자가 새 세션마다 손으로 다시 가르쳐야 했던 직접적 기제가 그것이다.

원하는 동작: 라운드가 나르던 것이 세션이 이미 읽는 자리에 착지하고, 거기 있다는 것을 알아야만 도달하는
계층이 존재하지 않는다.

선택한 경계: 라운드 계층을 제거한다. 제거 전에 계획의 읽기 범위 안에서 분류했다 — 지속 정본은
`docs/working-method.md` 와 `docs/design.md` 로, 결정과 기각은 `docs/decisions/` 로,
방향과 남은 한계는 `docs/direction.md` 와 `docs/backlog.md` 로, 소모된 발판(구현 명세·검증
계획·크기 예산·그날의 수치)은 버린다. 분류는 76편을 다 덮지 못했지만, 옛 기록은 대대적 리뉴얼 중인 과거 자료라 참고일 뿐이다. git 태그 **`rounds-archive-v1`** 이 76편 원본을 전부 보관하고, 그 태그명을 `docs/README.md`·`docs/design.md`·`docs/direction.md`
가 기록한다. 릴리스마다 무엇을 남기는지는 DD-113 이 고정한다. **이 계층을 되살리지 않는다.** 저장소
검사가 `docs/rounds/`·`docs/blueprints/` 가 돌아오지 않았고 `AGENTS.md` 가 그것을 이름 부르지 않음을 단언한다.

경계가 필요한 이유: 쓰였는데 도달할 수 없는 문서는 없는 문서보다 나쁘다. 지식이 기록된 것처럼 보이게
만들기 때문이다. 그것이 열두 릴리스 쌓여 소유자가 서술한 상태가 됐다 — 모든 에이전트가 빈 상태로
시작하고, 쓸만해지기까지 몇 시간의 교정.

기각한 대안: **보고서만 남기고 나머지를 보관** — 좌초한 정본이 있던 곳은 보고서가 아니었다. 남기면
읽기 비용만 보존되고 가치는 아니다. **배선 없는 `history/` 디렉터리로 전부 이동** — 바이트는 남지만
하중을 받는 단계는 여전히 승격이고, 그 디렉터리에 다시 규칙이 필요해진다. Git 이 이미 그 디렉터리다.
**승격 없이 삭제** — 그 계획들의 §2·§3 에 있던 자산이 이번 개편이 존재하는 이유다.

영향 좌표: `docs/rounds/`(제거), `docs/blueprints/`(제거), `docs/working-method.md`(신설),
`docs/direction.md`(신설), `docs/design.md`,
`docs/maintenance-protocol.md`(§5 라운드 기록 제거, 7절로 재번호),
`scripts/repository-invariants.test.js`, git 태그 `rounds-archive-v1`.

릴리스 기록이 필요하다는 관측이 된다.
