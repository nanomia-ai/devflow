# DD-61 · 경량 변경(tweak)은 커밋이 곧 기록이다

- 상태: 유효 · 일부 정정 → DD-66 (v0.14.2)
- 주제: 작업 트리와 카드
- 도입: v0.14.0
- 최종 수정: 2026-08-13

v0.13.0 행의 "작으니까 기록 안 함은 만들지 않는다"의 기록된 사유(기록되지 않는 경로가 기본길이 된다)는 이렇게 반박된다: 커밋이 기록이다 — 이 경로는 기록을 건너뛰지 않고 기록의 층을 바꾸며, 소유자가 방향을 직접 정정했다(버튼 문구·색 수준은 diff가 완전한 기록이고 돌아볼 일이 거의 없다). 세 질문 게이트 — 사용자가 보는 전제→결과 전이가 바뀌는가 · 설계 결정을 낳거나 기존 결정·디자인 토큰과 충돌하는가 · 다음 작업자가 몰라서 틀릴 함정을 남기는가 — 전부 "아니오"이고 어느 것도 불확실하지 않을 때만: 카드·journal·검토 없이 존재하는 Layer 0 네 문서를 읽고, 수정하고, 변경 파일에 닿는 가장 싼 확인 1회 뒤 `tweak` 커밋 하나로 끝낸다. `.devflow/` 경로는 건드리지 않는다. 지식이 있는 변경은 게이트가 문서층으로 보내고 발견→갱신 표는 변경 크기와 무관하게 계속 적용된다. 경량 요청만 받은 새 세션은 상태 복원을 생략한다 — 이 경로는 기존 기록을 소비하지도 공유 상태를 바꾸지도 않으므로 그물 우회가 무해하고, "코드를 보고 추론해도 되는 경우가 훌륭히 존재한다"는 소유자 요구의 첫 착지다. 판정이 진행 중 뒤집히면 멈추고 정식 경로로 전환한다. 남는 위험은 오분류 하나 — 관찰 항목 (2026-08-13 정정: "그물 우회가 무해하다"는 v0.14.0 감사가 재현으로 일부 반박했다 — 경량 커밋도 HEAD를 전진시키므로 base 커밋 id에 고정된 `라우팅 준비` 복구를 정합성 이상으로 바꾸고, 낡은 checkout의 문서는 통합의 최신 결정과 충돌하는 "아니오"를 만든다. DD-66의 착지 확인이 이를 막는다; 상태 복원 생략 자체는 유지된다. 판정 입력에는 항목이 이름·용어에 닿을 수 있을 때 존재하는 glossary.md가 더해졌다 — 용어 결정은 거기에만 살고, 인근 코드는 표기를 보여줄 뿐 결정임을 보여주지 못한다)
