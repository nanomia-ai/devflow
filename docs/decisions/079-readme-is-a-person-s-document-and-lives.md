# DD-79 · README는 사람의 문서이고 AI의 읽기 집합 밖에 산다 — 읽지도 갱신하지도 판정 근거로 삼지도 않으며, 이 선은 README가 돌아온 뒤에도 그대로다

- 상태: 유효
- 주제: 정체성 · 배포 · 플랫폼
- 도입: v0.18.5
- 최종 수정: 2026-08-20

관측된 문제: 소유자가 **이전부터** README를 참고하지 말라고 지시했는데 배선이 계속 살아
있었다. 지시가 어느 결정에도 기록되지 않아 라운드마다 조용히 되살아난 것이다. 실물로 전수하니
세 방향이 다 살아 있었다 — 정본이 잔여 위험을 「README 지침」에 넘겼고
(`skills/principles/SKILL.md:557`), 역할 계약이 자기 발견 경로에 README를 셋 중 하나로 적었고
(`skills/principles/coordinator.md:2`), 유지보수 프로토콜 §6이 AI에게 README 산문을 어떻게
**고칠지** 가르쳤으며, 시험 단정이 README 내용을 판정 근거로 읽었고, 매트릭스 두 칸이
「README에 지침 존재」를 검증 조건으로 걸어 뒀다. 스킬 개발이 잦아지면서 그때마다 README를
인용하고 갱신하는 과정이 반복 비용이 됐다.

원하는 행동: README는 사람이 읽는 문서이고, AI의 작업이 그것 때문에 어떤 영향도 받지 않는다.
무엇을 언제 쓸지는 소유자가 직접 정한다.

선택한 경계: 스킬·도구·절차가 닿는 범위는 `skills/`·`scripts/`·`hooks/`·`codex/`·`docs/`·
manifest까지이고 README는 그 바깥이다 — 읽지도, 갱신하지도, 판정 근거로 삼지도 않는다.
**이 선은 README가 돌아온 뒤에도 그대로다.** 돌아오는 것은 파일이지 배선이 아니다.

경계가 필요한 이유: 「유예」로 적으면 다음 세션이 「파일이 돌아오면 배선도 돌아온다」로 읽고,
그것이 바로 이번에 되살아난 경로다. 삭제만으로도 부족하다 — 삭제는 파일을 없애지 선을 긋지
않는다. 선으로 적어야 파일이 돌아와도 배선이 안 따라온다. 대가를 하나 정직하게 적는다:
devflow가 **막아 주지 않는다고 선언한** 목록의 정본이 이 선 밖으로 나갔다. 그 목록을 AI가
읽는 자리로 옮기는 것이 답처럼 보이지만, 그것은 새 거처를 만드는 일이고 소유자는 옮기라고
하지 않았다. 그 목록은 소유자의 것으로 남는다.

기각한 대안: **표를 `docs/design.md`로 옮긴다** — 사람용 문장에 새 거처를 만드는 것이고,
「한 사실, 하나의 거처」가 그 사본을 금지한다. **§6을 유예 표시로 남긴다** — 위의 이유로
기각. **AGENTS.md에도 같은 경계를 적는다** — 최소 진입 게이트에 매 세션 비용을 물리고 같은
사실을 두 곳에 둔다. 경계의 거처는 `docs/design_ko.md` 하나다.

영향 좌표: `docs/design{,_ko}.md`(경계 문단·불변식 절·문서 지도), `AGENTS.md`(배선표 행·
「한 사실 한 거처」 목록·온보딩 제외 목록), `docs/maintenance-protocol{,_ko}.md`
(§1·§2 쌍 목록과 한국어 예외·§3 착지 표·§6·§8 점검표), `skills/principles/SKILL{,_ko}.md`,
`skills/principles/coordinator{,_ko}.md`, `scripts/repository-invariants.test.js`,
`scripts/session-start.test.js`, `docs/usecase-matrix_ko.md` 3.4·A20 칸,
`docs/design-backlog{,_ko}.md`.
재검토 조건: 소유자가 README를 AI 작업의 입력으로 다시 쓰겠다고 정할 때. 그때 되돌릴 것은
파일이 아니라 이 선이다.
