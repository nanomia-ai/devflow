# DD-34 · Git 작업 트리의 열린 rebase·merge는 모든 devflow 라우팅보다 먼저 사용자에게 돌린다

- 상태: 유효
- 주제: Git 기계와 중단 복구
- 도입: v0.9.21
- 최종 수정: 2026-08-13

통합 명령 뒤 세션이 끊기면 Git의 열린 작업과 충돌 index가 이미 영속 상태다. 이를 점유 작업으로 오인하면 devflow 상태를 잘못 덧쓸 수 있고, 자동 중단은 사용자가 해소한 내용을 버릴 수 있다. 사용자 결정 전에는 아무 경로나 commit도 바꾸지 않고, 계속할 때도 확인된 충돌 해소와 기존 Git 작업의 commit만 허용한 뒤 정합성 점검을 처음부터 다시 실행한다. 비-Git 프로젝트에는 이 상태가 없으므로 관문을 적용하거나 Git을 초기화하지 않는다
