# DD-47 · 점유는 깊이 1 단위 축, 선택은 정본 후보 순서 하나

- 상태: 유효 · 일부 정정 → DD-60 (v0.14.0)
- 주제: 동시성 · 점유 · 통합
- 도입: v0.12.0
- 최종 검토: 2026-09-11

트리와 능력 문서는 이미 도메인 축인데 점유만 사람 축에 묶여 있었다. `.wip.`를 (id × 깊이 1 단위)로 키잉하면 새 식별자 0으로 동시 작업이 표현되고, 정합성 1번의 두 예외(상호 병렬 승인·증거 대기)는 원래 한 능력 안의 예외이므로 위치가 정확히 맞는다. 그 위에서 "다음에 무엇"을 묻는 자리가 여럿이라 답이 갈렸다 — 정본 후보 순서가 사용자 지목 카드 → 세션 지목 단위 → 승계 단위 → 나머지로 한 번만 정의한다. 이 순서는 어느 라우팅 행이 일치하는지를 바꾸지 않고 준비되지 않은 카드를 준비시키지도 않는다. 인식 기계는 도메인 진입에만 있던 것을 정본으로 올리고 resume·기준선 판정은 인용으로 바꿨다. 대화의 변경 요청 행은 기획이 제안한 「점유 카드 행 아래」가 아니라 그 위에 둔다 — 같은 요청의 영속 형태인 `유지보수 라우팅 대기` 행이 이미 점유보다 위에 있고, 점유가 여러 단위에 동시에 있는 것이 정상이 된 이상 아래에 두면 요청이 사실상 기록되지 않는다. 한 사람의 두 터미널은 같은 id를 쓰므로 디스크가 구분하지 못한다 — 그 한계는 감추지 않고 README에 적고, resume 보고의 승인 절차가 실제 분리 장치다. **v0.14.0에서 정정**: 점유 키의 단위 축 절반이 물러났다 — "한 id 한 단위 한 점유"는 1인 1터미널 가정으로 판명되어 자유 병렬로 대체됐고, 정합성 1번의 두 예외 문구도 함께 갔다(1번은 고아 점유 탐지로 재정의). 정본 후보 순서와 요청 기록 행 배치는 그대로 서 있다
