# DD-72 · 역할을 따로 지정하지 않은 버전 구현은 report_ko.md 하나를 기본 라운드 기록으로 남긴다

- 상태: 대체됨 → DD-114 (v0.26.0)
- 주제: 정체성 · 배포 · 플랫폼
- 도입: v0.16.2
- 최종 수정: 2026-08-16

관찰된 문제: 구 규율은 자체 버전을 가질 만큼 큰 변경을 라운드라고 하면서 라운드가 기록을
남긴다고 했지만, 동시에 소유자가 요청한 역할만 만들라고 했다. 독립 감리가 역할을 지정하지 않은
버전 구현에서 기록을 만들 수도, 생략할 수도 없는 문자 충돌과 버전 배선에서 그 규칙에 닿지 않는
경로를 확인했다.

원하는 동작: 버전 구현은 검증·한계가 다음 세션에 남고, plan·request·audit 같은 다른 역할은
소유자가 요청하지 않으면 생기지 않는다.

선택한 경계: 버전 구현 요청이 라운드 문서 역할을 따로 지정하지 않았을 때에만
`docs/rounds/<version>/report_ko.md` 하나가 기본 기록이다. 버전 상승 배선은 라운드 규약을 열며,
그 밖의 역할 생성과 기존 기록 수정에는 이 기본값이 번지지 않는다.

필요한 이유: report는 실제 배포·검증·미수리 소견·한계를 소유하는 이미 존재하는 역할이라 새
개념을 만들지 않고도 버전과 증거를 잇는다. plan을 기본값으로 삼으면 구현 뒤에 계획을 소급
작성하고, 아무 기록도 만들지 않으면 새 세션이 CHANGELOG만 보고 검증 경계를 추측하게 된다.

기각한 대안: 모든 버전에 전체 문서 묶음을 만드는 것은 비용과 허위 누락을 늘린다. 역할 없는
자유 형식 기록은 문서 지도를 우회하고, 기존 라운드에 임의로 합치는 방식은 버전 계보를 흐린다.

영향 좌표: `AGENTS.md`, `docs/maintenance-protocol{_ko}.md`,
`docs/rounds/<version>/report_ko.md`, `scripts/repository-invariants.test.js`. 역할을 지정하지 않은
버전 구현에서 report보다 더 작은 기존 역할이 같은 증거를 손실 없이 소유할 수 있거나, 수리
릴리스의 앞 라운드 귀속 규칙과 충돌하는 실제 장면이 생기면 다시 검토한다.
