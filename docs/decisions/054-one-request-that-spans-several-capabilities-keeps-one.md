# DD-54 · 여러 능력에 걸친 요청은 출처 하나와 부모마다 마커 하나를 갖는다

- 상태: 유효 · 일부 정정 → DD-87 (v0.19.0), DD-92 (v0.20.0)
- 주제: 작업 트리와 카드
- 도입: v0.13.0
- 날짜: 2026-08-13
- 날짜 근거: git 추정 (CHANGELOG에 해당 버전 없음)

매핑이 단수로 쓰여 있었고("대응하는 능력 폴더로 간다") 세 곳이 정해지는 경우가 정의되지 않았다. 문자 그대로 읽는 AI가 하나를 고르면 나머지가 조용히 사라지고 journal 줄까지 지워져 복구도 안 된다 - 소유자가 가장 경계하는 소실이다. 클라이언트의 수정 리스트를 한 세션에서 일괄 처리하는 것은 일상이다. 부모들의 마커가 같은 정확한 출처 locator를 공유하면 새 batch id 없이 묶음의 정체성이 생겨 resume이 함께 복구하고, 실행 제안과 승인을 한 번으로 묶으면 스무 개짜리 목록에 승인이 여러 번 필요해지지 않으며, 모호하거나 은퇴한 단위는 절반만 계획하고 나머지를 잃는 대신 시작 커밋 전에 묻는다
