# 유즈케이스 전수와 설계 대조 — 사람의 요청 형태 × AI의 진입 지점

지위: **공용 검증 수단** (버전 없는 상시 문서 · 배포 산출물 아님 · 한국어 전용)
계보: v0.13.0 라운드의 유즈케이스 매트릭스 2판에서 승격(2026-08-13, 소유자 결정). 3판 =
승격 + v0.14.0 결정 반영.

**갱신 규율**: 대화나 실전에서 새 요청 형태·진입 지점이 발견되면 이 문서에 행을
추가한다. **릴리스 검증마다 전 칸을 재판정한다.** 0.14.0의 예정 칸들은 2026-08-13 구현 대조(독립
문자 실행 워커 4시나리오 + 반증자 + 실측 fixture)로 전환 완료 — 남은 공백 0. 다음 릴리스가
칸을 바꾸면 같은 절차로 재판정한다.

---

## 0. 이 문서의 렌즈

devflow의 존재 목적: **사람이 AI와 작업하며 쌓는 개발 데이터를 자동으로 축적하고,
그것을 다음 AI가 이해할 수 있게 만드는 것.** 모든 판정은 소유자가 준 세 축으로 한다.

```
① 내구성   이 변수에서 크게 망가지지 않는가 — 특히 데이터가 절대 누락되지 않는가
② 토큰     AI가 진입할 때 지나치게 소모하지 않는가
③ 분별     남겨야 할 기록과 아닌 것을 옳게 가르는가
```

판정 어휘: **정합**(세 축에 든다) · **긴장**(비용이 있으나 설계가 이유를 기록했다) ·
**공백**(설계에 답이 없다). 릴리스 플랜이 닫기로 한 칸은 `[예정]`으로 표시했다가 구현
대조 후 전환한다(0.14.0분은 전환 완료). 크게 망가짐의 정의는 ①의 위반, 그중에서도 조용한 자료 소실이다.

③의 정본 원칙(v0.14.0에서 확정): **변경의 크기가 아니라 남는 지식의 유무로 가른다.
diff가 이미 완전한 기록인 변경은 커밋으로 끝낸다. 향후 판단을 바꿀 수 있는 것 —
전이·결정·함정 — 만 문서로 올린다.**

## 3. 대표 교차 워크

1·2판의 워크 중 판정이 유지되는 것(솔로 continue · 방치 복귀 · 파킹 · 게시 분류 ·
위임·역할 A6·A7·A13 · 주입 기억 A14 · 구버전 흔적 A15 · 비도입자 H32 · 수동 revert
H19 · 비코드 카드 H20 · 워크트리 이사 H25 · 긴급 우회 H17)은 결론만 유지한다:
정합. 아래는 v0.14.0 결정이 판정을 바꾸는 칸과 3판 신규 칸이다.

### 3.1 H22 — 한 도메인 다중 터미널 [판정 교체]

2판 판정: 공백(파킹 우회가 형제 작업을 쓸어 커밋 + 점유 전이 규칙이 선견지명 요구).
**정합** (2026-08-13 재판정: 문자 실행 워커 S1 + 3점유 fixture 통과) — G3 자유 병렬: 점유는 질문 없이 즉시, 정보 한 줄만. 체크포인트류는
"이 세션이 만든 변경만". 검증 시 확인할 것: 3점유 fixture에서 질문 0회, 형제 diff
커밋 경로 0.

### 3.2 H5·H6·H12 — 사소한 변경과 상태 질문 [판정 교체]

2판 판정: 긴장(카드 하나짜리 세션에 상각 논리가 안 듦 — P1).
**정합** (2026-08-13 재판정: 워커 S2가 경량 진입·커밋 형식·전환 경로를 그대로 걸음) — 축 B 경량 차선: 세 질문 게이트(전이/결정·충돌/함정) 전부 "아니오"면
카드·journal 없이 Layer 0 네 문서 + 수정 + `tweak` 커밋 하나. H12(상태 질문)는 경량
대상이 아니고(변경이 아님) 진입 고정비가 남는다 — 그 축소는 D11(규칙 소비자별 분할,
다음 릴리스)의 몫으로 긴장 유지.

### 3.3 H27×A12 — 봉쇄 상태의 기록 [판정 교체]

2판 판정: 공백 — 유일한 조용한 소실 경로(봉쇄 중 요청이 대화에만 존재하다 증발).
**정합** (2026-08-13 재판정: 워커 S3 — 봉쇄 중 요청 즉시 기록, 세션 사망 후 다음 세션이 절차 6에서 발견) — G2: 발급·점유·소비가 아닌 journal 덧붙임은 봉쇄 중에도 기록·로컬
커밋. 검증 시 확인할 것: 봉쇄 fixture에서 요청 발화 → 세션 사망 → 다음 세션이
브랜치에서 그 줄을 읽는다.

### 3.4 H37 — 같은 카드를 두 터미널에 동시 지시 [3판 신규]

```
디스크에는 터미널 식별자가 없다(실측으로 확정된 물리 한계 — "터미널별 이름표"는
커밋 작성자 훼손으로 기각). 두 터미널 다 같은 사람의 정당한 점유 이어받기로 보인다.
```

**판정: 보장 밖 성격의 긴장.** 기계 방어 불가. 방어선: 진입 보고의 미커밋 변경
표시(사람이 알아챌 단서) + README 지침("같은 카드를 두 터미널에 시키지 말 것") +
사용자의 의도 없이는 발생하지 않는 경로라는 사실. 검증 시 확인할 것: README에 지침
존재, 정본 상태 표기에 "한 카드는 한 번에 한 세션" 문장 존재.

### 3.5 H38 — 다중 점유 상태의 무지목 재개 [3판 신규]

```
자유 병렬로 내 점유 여럿이 일상이 되면, 새 터미널의 "이어서 해줘"가 후보 순서
1위 점유에 붙는다 — 그 카드는 다른 터미널이 지금 돌리는 중일 수 있다.
```

**정합** (2026-08-13 재판정: 워커 S1 — 무지목 재개에서 목록 제시 후 질문) — A6: 내 점유가 둘 이상이고 대화가 카드도 단위도 지목하지 않으면
목록을 보이고 묻는다(기존 "두 단위 이상이면 묻는다" 규칙의 점유판 — 겹쳤을 때만
묻는다는 소유자 기준에 부합). 검증 시 확인할 것: 점유 1개면 질문 0회, 2개+무지목만
1회.

### 3.6 H39 — 경량 변경 도중 판정 뒤집힘 [3판 신규]

```
문구만 고치려다 열림 조건까지 바꿔야 한다는 것을 발견 — 게이트 ①이 사후에 "예"가 됨.
```

**정합** (2026-08-13 재판정: 워커 S2 — 전환 지시를 그대로 걸음; 잔여 수정 인수는 사용자 확인 경로로 보강) — B1 ⑤: 멈추고 보고, 정식 경로(요청의 journal 기록부터)로 전환,
수정분은 작업 트리에 남겨 카드의 첫 체크포인트가 흡수. 관찰 항목: 오분류율(경량으로
끝났는데 실제로 전이가 바뀐 경우 — digest와 Scope head 강등이 사후 신호).

### 3.7 A19 — 경량 진입 [3판 신규]

**정합** (2026-08-13 재판정: 워커 S2 — 트리·journal 읽기 0) — G6: 게이트 통과 시 상태 복원 생략, Layer 0 네 문서만. 위험은
오분류 하나(3.6과 같은 뿌리). 소유자 §2.6("코드를 보고 추론해야 하는 경우도 훌륭히
존재한다")이 설계에 처음 착지하는 지점. 검증 시 확인할 것: 경량 fixture에서
트리·journal 읽기 0회, 열린 rebase/merge 게이트는 여전히 동작.

### 3.8 A4 — 하위 폴더 진입 [판정 교체]

2판 판정: 공백(중첩 devflow 루트 생성 가능).
**정합** (2026-08-13 재판정: 정본 문장 확인) — E1: 정본 한 문장("모든 devflow 경로는 저장소 루트 기준 —
`git rev-parse --show-toplevel`로 해석").

### 3.9 H26·H30 — 좌초된 흐름 [유지]

**긴장 — 관찰 등재.** Git이 브랜치를 보존하므로 소실이 아니라 가시성 문제(이중 구현
위험). 예비안(resume의 유계 브랜치 열거)은 `design-backlog` 관찰 항목에 기록. 실전 관측
후 재판정.
