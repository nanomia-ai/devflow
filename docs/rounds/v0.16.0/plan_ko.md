# v0.16.0 계획 — 오케스트레이터는 선언된 역할이고, devflow의 동작은 바뀌지 않는다

상태: **구현 계획 · 소유자 진행 승인 완료** · 작성 2026-08-15

이 라운드의 요청은 대화에서 왔고 여기 기록한다. 소유자가 물은 것은 "오케스트레이터·코디네이터
아래에서 devflow를 돌릴 때 파일 체계와 메모리 계층이 무리 없이 도는가"였고, 이어서 "가장
깔끔하게 해결하는 방법"을 요구했다. 소유자 확정 사항 셋: **이름은 `coordinator`** · 발견 경로
범위와 기계 검사 여부는 **구현 세션의 능동 판단** · **v0.16.0으로 진행 허용, 완료 후 충분한
검증**.

---

## 1. 왜 — 관찰된 것

2026-08-15에 이 저장소를 오케스트레이션으로 개발하면서, 같은 구조 아래에서 devflow **자신을**
돌릴 때의 호환성을 배포 원문으로 점검했다. 결과는 두 갈래였다.

**devflow는 이미 이 형태를 설계에 담고 있다.** DD-53은 한 작업 폴더의 여러 세션을 정상으로
선언하고 그 안전을 락이 아니라 측정된 다섯 줄로 두었으며, 규칙 정본은 워크트리를 안전장치가
아니라 빌드 격리 선택으로 못 박는다. split의 실행 제안은 순서(`의존`)·병렬(`승인`의
`parallel:`)·등급(`Tier`)을 이미 디스패치 계획의 형태로 낸다. 병렬 조건 문장은
`a single agent's compile error breaks the whole screen`이라고 적어, 에이전트 여럿이 동시에
도는 상황을 이미 전제한다.

**그런데 그 형태를 모는 쪽의 의무는 어디에도 없다.** README의 보장 밖 표는 두 clone 문제를
설명하며 해법으로 `You need a shared ref, a coordinator, or an assignment made in advance`를
지목하는데, 그 coordinator가 무엇을 지켜야 하는지를 말하는 문장이 저장소에 하나도 없다.

호환성 점검이 뽑은 오케스트레이터의 의무는 아홉이고, 그중 셋은 devflow가 이미 감지한다 —
카드 모호성은 resume이 추측 대신 묻고, 잘못된 커밋은 상태 기계가 정합성 이상으로 보고하며,
손 편집은 DD-38의 승인 신선도가 무효화한다. **감지할 수 없는 것은 셋이다**: 사람 관문을
오케스트레이터가 대신 답하는 것, 파일 전체 재작성, 지식이 디스크 밖 채널로만 흐르는 것.
셋 다 신뢰 경계 **바깥**의 행동이라 어떤 메커니즘으로도 막을 수 없다.

따라서 빠진 것은 메커니즘이 아니라 **계약**이다. 그리고 devflow에는 이미 그 장치가 있다 —
역할 계약(DD-19: 스킬 옆 동반 파일 하나, 등록 에이전트 아님, 원문 그대로 브리핑).

특히 다섯째 의무(전체 재작성 금지)는 시급하다. devflow의 유일한 조용한 파괴 경로가 정확히
그것인데(`only a whole rewrite overwrites quietly`), 파일을 통째로 덮어쓰는 것은 AI 에이전트의
기본 습관이다. 사람 팀에서 드문 행동이 에이전트 플릿에서는 기본값이다.

다르게 판단하면 근거와 함께 보고한다.

## 3. 계약이 담을 아홉 조항

각 조항은 삭제하면 다시 열리는 실패 경로를 하나씩 갖는다. 조항 밖의 설명·요령·도구 사용법은
싣지 않는다.

1. **디스패치는 카드 번호와 작업 폴더를 명명한다.** 없으면 resume이 사람에게 할 질문을 워커가
   받아 임의로 답한다. README 보장 밖 표의 `an assignment made in advance`가 이 조항이다.
2. **워커가 자기 devflow 커밋을 하고, 코디네이터는 커밋하지 않는다.** 점유 rename·`NN.N wip:`·
   `split — begin`·경계 커밋은 이름이 곧 상태 전이다.
3. **코디네이터는 저장소를 편집하지 않는다.** 핵심 문서는 절차 또는 소유 스킬 재실행으로만
   바뀌고, 손 편집은 카드의 `승인`을 무효화한다.
4. **멈추고 묻는 지점은 사람에게 간다.** 모아서 한 번에 올릴 수는 있어도 대신 답할 수 없다.
   재관측 2 이상은 원문이 `the human`을 명시한다 — 대리 응답은 자동 수리 루프의 상한을 그
   자리에서 없앤다.
5. **워커에게 부분 편집을 지시하고 파일 전체 재작성을 금지한다.** devflow의 유일한 조용한
   덮어쓰기 경로다.
6. **메시지는 라우팅을 나르고 지식은 디스크가 나른다.** 세션이 죽어도 디스크가 들고 있다는
   보장이 오케스트레이터의 채널에서 끊긴다. 중복은 허용, 대체는 금지.
7. **상태는 워커 보고가 아니라 트리와 통합 브랜치에서 읽는다.** 요약을 원문보다 신뢰하는 실패.
8. **스케줄은 카드가 이미 말한 것을 따른다.** `의존`·`parallel:`·`Tier`를 읽고, 저장소 전역
   완료 신호와 공유 dev server·DB·포트를 쓰는 작업은 순차로 둔다. 대상 능력 폴더에 미커밋
   변경이 있는 동안 그 능력의 verify를 배치하지 않는다.
9. **워커의 신원은 소유자의 id를 상속한다.** 구분은 신원이 아니라 배정에서 온다 — 워커마다
   방을 만들면 `ids are never reused` 규칙 때문에 죽은 방이 쌓인다.

## 4. 이번에 만들지 않는 것

- **오케스트레이션 상태를 디스크에 적지 않는다.** 새 상태는 그것을 누가 언제 지우는가라는
  낡음 문제를 데려오고, devflow가 그것을 알아도 바꿀 동작이 없다.
- **devflow의 동작을 오케스트레이션 여부로 분기하지 않는다.** 분기 후보를 넷 검토했고 —
  카드 모호성 질문 억제(디스패치가 이미 해소), 관문을 코디네이터로 전환(유해), 완료 신호 자동
  축소(이미 규칙의 선호), 전체 재작성 완화(더 나쁨) — 하나도 이득이 없다.
- **등록 스킬로 만들지 않는다.** 오케스트레이터는 흐름 안의 단계가 아니라 위의 행위자다.
  DD-19가 역할 계약을 등록 에이전트로 만들지 않기로 한 선례를 따른다.
- **워커별 방·id를 만들지 않는다.**
- **강제 장치를 만들지 않는다.** 신뢰 경계 밖이므로 선언이 전부다 —
  `One rule stops it; nothing stops you from breaking that rule`.

## 5. 기계 검사 (F8)

쌍을 AGENTS에 등록하면 구조 동형성·배포물 한글 0 검사가 자동으로 따라온다. 여기에 셋을 더한다.

1. `scripts/session-start.js`의 출력 텍스트가 계약 파일명을 담는다.
2. `skills/principles/SKILL.md`가 계약 파일을 지목한다.
3. **`principles` 외의 어떤 `skills/**` 파일도 계약을 참조하지 않는다** — 진입 고정비 0이라는
   성질을 미래 편집으로부터 지키는 검사다.

기존 테스트 파일의 스타일을 따르고 새 test 블록을 만들지 않는다. 전체 suite는 계속 전부
통과해야 한다.

## 6. 알려진 경계 — 숨기지 않는다

- **훅은 devflow 상태가 이미 있는 저장소에서만 발화한다**(`session-start.js`의 조기 종료).
  상태가 생기기 전에 시작한 오케스트레이터 세션은 훅으로 닿지 않고 README·정본 경로에만 닿는다.
  다만 위험한 오케스트레이션(카드 병렬 점유)은 트리가 생긴 뒤에만 존재하므로, 포인터는 그것이
  처음 문제가 되는 순간보다 먼저 도착한다.
- **계약은 강제되지 않는다.** 무시하는 오케스트레이터를 막는 장치는 없다.

## 7. 검증 계획

소유자 요구는 "완료 후 충분한 검증"이다. 이 라운드는 배포 동작 변경이 작으므로 규모를 맞춘다.

1. **한국어 원본 → 독립 검증(신선 컨텍스트) → 재검토 → 수리 → 영문 번역 → 영문 검증**의 교차
   루프. 이전 두 라운드와 같은 리듬.
2. **독립 감사 두 렌즈**(지침 §3-3에서 선택, §8 브리핑 원문 전달):
   - **뺄셈 감사** — 아홉 조항 각각에 "삭제하면 다시 열리는 실패 경로"를 대게 한다. 못 대는
     조항은 삭제 소견이다. 이 계약은 새 규칙 아홉 줄을 배포에 더하므로 이 렌즈가 1순위다.
   - **문자 실행 워커** — 아래 시나리오를 계약 문장만으로 걷는다.
3. **고정 시나리오**: O1 카드 미지정 디스패치 · O2 워커 둘 같은 카드 · O3 구현 중 능력의 verify
   배치 · O4 저장소 전역 완료 신호 병렬 · O5 재관측 2 이상 관문 도달 · O6 워커가 파일 전체
   재작성 시도 · O7 지식을 메시지로만 전달 · O8 코디네이터가 커밋·편집 시도 · O9 워크트리 삭제
   전 미통합 체크포인트 · O10 devflow 상태 없는 새 저장소에서 시작(훅 미발화 경계).
4. **정합 대조**: 계약 문장이 인용·전제하는 원문(DD-19·DD-38·DD-50·DD-53·README 보장 밖 표·
   split 병렬 조건·verify 미커밋 거부·재관측 2 관문)이 실제로 그렇게 적혀 있는지 전수 확인.
5. **비오염 확인**: `skills/**`의 스킬 본문이 F3의 한 줄 외에 diff 0인지 기계로 확인.
6. 수리 뒤 유계 재감사 1회. 지침 §5 종료 조건을 조항별로 평가해 보고한다.

## 9. 정본 승격

- **DD-70**: 오케스트레이터는 devflow의 단계가 아니라 선언된 역할이며, 그 의무는 역할 계약
  하나가 소유하고, devflow의 동작·상태는 오케스트레이션 여부로 분기하지 않는다.

- 용어표: `coordinator`가 새 정본 용어인지 판정한다 — README가 이미 쓰는 말이므로 새로 만드는
  것이 아니라 고정하는 것이고, 한국어 대응어를 정할 때만 행을 더한다.
- 매트릭스: §1~§2를 읽고 새 행 필요 여부를 판정(F9).
