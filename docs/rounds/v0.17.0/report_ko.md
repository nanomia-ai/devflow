# v0.17.0 구현 보고 — 기획의 마지막 출력이 다음 세션까지 살아남게 하다

날짜: 2026-08-16  
비교 기준: `6eb09117868b1343993185603148c5c221702f14` (v0.17.0 계획 확정)

## 왜

synky 실사용에서는 arch.md와 code-style.md가 착지한 뒤 컨텍스트가 소진되어 arch의 마지막
출력인 능력 문서 6장이 한 장도 만들어지지 않았다. 확정 문서 사이의 경계는 커밋과 resume이
보존했고 한 문서를 확인받는 도중에는 값싼 중간 착지가 없었다. 이번 구현은 결함이 있던 세 번째
구간만 닫고, 감사에서 철회된 넓은 처방은 기각 계보와 백로그에 남겼다.

## 실제 배포 (Actually shipped)

- arch는 능력 문서 절을 시작하기 전에 기대 문서 수를 말한다. 컨텍스트 경고가 있으면 확정된
  Layer 0 커밋에서 멈추고 arch가 아직 끝나지 않았음을 밝히며, 점유 카드가 없는 다음 세션이
  resume으로 들어와 그 절만 실행하게 한다.
- split은 첫 트리 개방 때 `devflow/project/capabilities/` 아래 파일이 0장이면 멈춘다.
  `Brownfield` 값에 따라 arch 또는 adopt로 보내고, 연기 실행은 이 게이트도 건너뛴다.
- arch.md 확인 직전에 ADR 세 조건을 통과한 결정을 전부 열거하고 각각 기록할지 확인한다.
  Components·Stack의 근거가 외부 계약 사실에 기대면 정확한 출처를 같은 줄에 남긴다.
- README는 HANDOFF.md가 인수인계 문서가 아니라 재계산 가능한 값 하나의 캐시이고 digest.md가
  요약이 아니라 commit hash bookmark임을 설명한다. Layer 0 경계에서 세션을 끝내고 resume으로
  잇는 법과 능력 문서가 Layer 0 뒤에 놓인다는 디렉터리 구조도 맞췄다.
- 유즈케이스 매트릭스에 H46·A20을 추가했다. 설계 대장에는 DD-73과 DR-47~DR-50을 착지시키고,
  백로그에는 계획 §4의 여덟 관찰과 두 정산 계보를 한영 1:1로 반영했다.
- 두 plugin manifest와 CHANGELOG를 0.17.0으로 맞췄다. 이 작업자는 이미 존재하던
  `skills/arch`·`skills/split` 및 README 변경을 추가 수정하지 않았다.

생성 경로는 이 파일 하나다. 삭제·이동 경로는 없다.

## 검증

- `node --test "scripts/*.test.js"`: 98/98 통과.
- 결정 색인과 본문의 ID 집합, ko↔en 구조 대응, 영어 배포물 한국어 0건 검사는 같은 실행에
  포함된다.
- 감사 지침 §5 정지 조항의 자기 검토: ①규칙 충돌·소실 경로 채택 소견은 0이지만 독립 감사는
  실행하지 않아 그 판정은 `미검증`, ②남은 소견이 0이라 양갈래 독해·표현 등급 분류는 해당 없음,
  ③수렴형 수리 여부와 새 해석 부재는 독립 재감사를 실행하지 않아 `미검증`이다. 유계 재감사도
  실행하지 않았다. 개인 회로 차단기 넷(같은 문장 3회 수리·구체적 오독 없는 혼동 주장·진자 운동·
  자기 이전 소견만을 근거로 삼음)은 발생하지 않았다.
- 진입 체계 변경이 아니므로 clean Claude·Codex 세션의 전후 동일 질문 비교는 해당 없음이다.

## 새 구속 결정 (New binding decisions)

- **DD-73 — 지식층과 능력 문서.** 확정 문서 사이와 확인 도중과 능력 문서 전 구간을 구분하고,
  arch의 규모·중단·재진입 경계, split의 0장 게이트, ADR 확인 단계, 외부 계약 출처 자리를 하나의
  생애로 묶었다. 기존 결정 색인 행의 상태는 바뀌지 않았다.
- 철회안은 구속 결정이 아니라 같은 주제의 기각 계보에 남겼다. DR-47은 Provisional 범위 확대,
  DR-48은 능력명↔폴더명 완화, DR-49는 Layer 0 초안 `.wip.` 접미사, DR-50은 design을 외부 자료
  권위 통로로 쓰는 안이다.

## 미수리 소견 (Unrepaired findings)

채택됐지만 이 라운드 범위에서 고치지 않은 구현 소견은 없다. 계획의 D-3과 §4 항목은 결함 수리
승인이 아니라 관측 조건을 가진 백로그이며, 새 런타임 규칙을 만들지 않았다.

## 남은 한계 (Remaining limitations)

- split의 새 게이트는 파일 0장만 잡는다. 기대 집합 중 1~N-1장인 부분 생성은 기존 resume과
  기준선 판정이 계속 소유한다.
- Layer 0 문서 확인 도중의 초안 상태에는 여전히 디스크 표현이 없다. 파일명 접미사 안은 기존
  금지 세 개와 봉쇄 환경에 막혔고, 백로그의 (A)/(B) 선택은 소유자 판단으로 남는다.
- arch.md가 이미 착지한 뒤 처음 발견된 미기록 ADR을 회수하는 정본 경로는 없다. DD-73은 착지
  전 심사만 닫는다.
- `verify_channel`의 planned/current 혼합, 활성 점유의 설계 구역 갱신 지연, adopt 중간 사망,
  상위 문서와 재파생의 비원자성, 확인 없는 능력 문서 byte 변경 두 경로, `Layer 0` 용어 갈림은
  실전 관측 조건과 함께 백로그에 남았다.
- synky-monorepo에서의 실제 `resume → arch 능력 문서 전용 분기 → split` 재현, 로컬 Codex
  snapshot refresh, Claude 재설치는 이 작업에서 실행하지 않았다.
- 구현 문안의 독립 감사와 재감사는 아직 실행하지 않았다. 자기 검토는 독립 감사를 대체하지 않는다.

## 다음 재검증 (Next revalidation)

synky-monorepo의 새 세션에서 resume을 실행해 능력 문서 6장 규모 고지, arch 전용 재진입,
6장 착지, 그 뒤 split 통과를 실제로 확인한다. 첫 부분 생성·사후 미기록 ADR·planned means 오호출
중 하나가 관측되면 각각 백로그의 해당 행을 다시 연다. 독립 구현 감사는 변경된 arch·split 영문과
DD-73·DR-47~DR-50 착지를 대상으로 감사 지침 §8 브리핑 그대로 실행하고, 수리가 생기면 한 번만
재감사한다.
